# HAI-001 · Who contributes what?

**Status: PROPOSED / NOT RUN**  
**Protocol version:** v0.1.0 task pack frozen for review, 2026-10-12  
**No participant data, measurements, or trial results exist.**

## Reproducible protocol components

The reviewable task pack, acceptance fixtures, scoring rubric, condition definitions and SHA-256 manifest are at [protocols/HAI-001/v0.1.0](../protocols/HAI-001/v0.1.0), with [instructions](../protocols/HAI-001/README.md). This is a preregistration draft, **not evidence of any effect**.

## Research question

How do model access and human iterative feedback affect correctness, completion time, and independent understanding when performing small software tasks?

## Predeclared hypotheses

- H1: Some forms of AI assistance reduce completion time relative to a human-only baseline.
- H2: Any advantage varies by task and model capability.
- H3: Bounded model-first output differs from iterative human–AI output in acceptance-test performance.
- H4: Greater AI involvement need not improve participant understanding.

These are hypotheses, not findings.

## Trial boundaries

The frozen pack has 12 candidate tasks, organized in four families with five acceptance fixtures per task. The tasks are **not yet empirically difficulty matched**; calibration must precede strong comparisons. Each arm uses the same 25-minute task ceiling and access to the same public fixtures.

The four arms are A (human only), B (human with one small local model), C (human with one cloud model), and D (one bounded model-first attempt without corrections). The D arm is not evidence of autonomous goal choice: a human selected and set up the problem.

For a valid human-participant study, preregister recruitment, informed consent, allocation seed, balanced assignment, exclusion criteria and independent scoring **before recruiting or running trials**. Repeating memorized tasks in one investigator's hands across arms creates severe carryover bias. The initial self-run pilot is useful as feasibility evidence, not population-level causal evidence.

## Scoring

Primary outcome: exact precommitted case passes out of five per task. Failure, missing output, crash and timeout count as failed cases. Secondary measurements: elapsed wall time, human active time, corrections, explanation, unaided modification performance and compute/cost estimates, with missing data reported explicitly.

All unfavorable, null or contradictory results must remain visible. A receipt schema check is not outcome verification, and green GitHub Actions means only that integrity/structure checks passed.

## Boundaries of interpretation

- No results have been collected.
- Open acceptance fixtures are not held-out evaluation.
- No treatment effect can be inferred from the synthetic example receipt.
- Running model-generated code requires a dedicated authorized sandbox; the current tools do not execute candidate code.
- No claim about AI consciousness, ownership of contributions, medical efficacy, or broad human cognitive changes follows from these tasks.
