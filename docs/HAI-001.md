# HAI-001 · Who contributes what?

**Status: PROPOSED / NOT RUN**  
**Protocol version:** 0.1.0 draft · 2026-10-12  
**No participant data, measurements, or results exist.**

## Research question

How do model access and human iterative feedback affect correctness, completion time, and independent understanding when performing small, matched software tasks?

## Hypotheses (testable, not assumed true)

H1: Some forms of AI assistance reduce completion time relative to a human-only baseline.  
H2: The advantage, if any, varies by task and model capability.  
H3: AI-only first-pass output will differ from a human–AI iterative output in acceptance-test performance.  
H4: Greater AI involvement need not improve participant understanding of the code.

## Study design proposal

A feasibility pilot, not a population estimate, with at least 12 independently specified, difficulty-matched tasks. If human participants other than the investigator join, specify consent, compensation where applicable, task assignment and any appropriate institutional review requirements before recruiting.

Four conditions:
- A / Human-only: no generative AI assistance.
- B / Human + local small model: iterative assistance permitted; record checkpoint and quantization.
- C / Human + cloud model: iterative assistance permitted; capture version and configuration.
- D / Model first-pass: a single bounded model attempt under equal task constraints, with no human mid-task correction. Human setup and scoring are still recorded.

The initial single-investigator pilot cannot isolate population-wide causal effects. For subsequent human-participant studies, randomize task-condition pairing, counterbalance order, prevent task leakage, use blinded scoring, and report uncertainty.

## Pre-commit task pack BEFORE running

Each task includes: neutral prompt, known starting state, external dependencies, time limit, functional tests, performance constraints, and difficulty rationale. Lock hash of the task pack prior to measurements; log any amendment as a new protocol version.

## Primary outcome

Proportion of predefined acceptance tests passed per task under the assigned condition. Tests must not be authored or altered in response to generated output.

## Secondary outcomes

- Active human time and wall time (report separately).
- Human decisions, corrections and retries.
- Maintainability score from blinded review with rubric.
- Explanation and unaided modification performance after task completion.
- Cost and compute usage where measurable.
- Failure rate, abstentions, and task cancellations.

## Analysis proposal

Report per-task paired differences, medians, distributions and confidence/uncertainty intervals rather than only a winning average. For a small pilot, use descriptive outcomes and avoid sweeping claims. Distinguish exploratory comparisons from preregistered metrics.
